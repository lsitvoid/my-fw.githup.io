给数据结构点人情味：从红黑树说起

课本把红黑树讲得很玄，其实它只回答一个问题： 怎么让二叉搜索树在最坏情况下也不长歪。

红黑树不追求完全平衡，只保证从根到叶子的最长路径 不超过最短路径的两倍——够用，且旋转次数少。

它的账本

  • 插入 / 删除 / 查找稳定在 O(log n)
  • 节点只多存 1 bit 颜色，比 AVL 的平衡因子省内存
  • 中序遍历天然有序，适合 std::map、Linux CFS 这类场景

代价

  • 插入删除要处理着色与旋转，实现复杂、代码量大
  • 范围查询要跨子树遍历，不如 B 树对缓存友好

后来我拿「241」三个数字设计过一门玩具三进制语言， 把指令集映射到三进制编码上，27 条指令刚好够一个栈机用。 具体见这篇文章里当时的推导。

1 -> 0   2 -> 1   4 -> 2
指令 = 三位三进制数，共 3^3 = 27 条
112 = ADD    114 = SUB    241 = HALT

玩具语言的意义不在能算什么，而在你亲手把 「编码 → 指令 → 执行」这条链走通一遍。数据结构也一样。
